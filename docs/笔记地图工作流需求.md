# llzz 技能深度优化需求：笔记地图工作流

## 1. 背景与目标

llzz 从「写入固定目录的随手记工具」升级为「以笔记地图为核心的 Obsidian 智能笔记工作流」。

- 目标 vault 不再写死，自动定位；当前用户指定 vault：`笔记个人-Kepano`（`obsidian://open?vault=笔记个人-Kepano&file=笔记地图`）。
- 核心机制：vault 根目录的 `笔记地图.md` 是 AI 的「规则大脑」，每次读写前必读。

## 2. 核心概念：笔记地图

- 位置：vault 根目录第一层 `笔记地图.md`。
- 内容四个区块：
  1. **入口**：各分类目录链接。
  2. **分类规则**：每个分类放什么内容、命名规范。
  3. **写入偏好**：用户要求（如笔记简洁、最多 N 个分类、callout 使用等）。
  4. **安全规则**：敏感信息不落地、私密目录默认不读。
- 地位：AI 每次读/写操作前必须先读它，严格按规则执行。

## 3. 四大工作流程

### 3.1 定位 vault（改造现有 find-vault.sh）

- 目标从「找林林总总目录」改为「定位 vault 根目录」。
- 候选来源优先级不变（obsidian.json → iCloud 容器 → 常见本地目录）。
- 选择规则：优先含 `笔记地图.md` 的 vault；多 vault 无法判断时列出候选让用户确认。
- 缓存到 `~/.config/llzz/vault-root`，支持 `LLZZ_VAULT` 覆盖。

### 3.2 笔记地图初始化（无地图时）

1. 扫描 vault 全部目录与文件（只看目录结构、标题、frontmatter，不读私密内容）。
2. 提出分类方案：分类数量与名称、每个分类的范围、现有文件的归属建议。
3. **必须经用户同意后才创建** `笔记地图.md`；用户有异议则按反馈调整后再次确认。

### 3.3 笔记地图维护（已有地图时）

1. 读取地图，对照实际目录结构检测「漂移」：
   - 地图引用的目录是否还存在。
   - 实际目录是否都有对应规则。
   - 规则是否过时（如长期未使用的分类）。
2. 提出优化建议，**经用户同意后更新地图**。

### 3.4 写入流程

1. 读笔记地图，提取分类规则与写入偏好。
2. 判断内容属于哪个分类。
3. 目标文件夹不存在 → 按地图规则自动创建。
4. 内容不命中任何现有分类：
   - 若地图限制分类数量（如最多 5 个）→ 归入最接近的分类或询问用户，**不擅自新增顶级分类**。
   - 无限制 → 可提议新分类，但需用户确认后才加入地图。
5. 文件内决策（追加旧文件 vs 新建）沿用现有文件选择规则（相关性 + 大小阈值）。
6. 写入后回复：写入路径、追加/新建、判断理由（一句话）。

### 3.5 读取 / 问答流程

1. 读笔记地图。
2. 推断用户问题最可能对应的分类文件夹，**优先在该文件夹内搜索**。
3. 未找到 → 再全量搜索。
4. 私密配置目录默认不读，除非用户明确要求。

## 4. 现状发现（首次维护的输入）

当前 `笔记个人-Kepano` 存在地图漂移：

- 地图入口引用 `生活笔记/`、`运营笔记/`、`学习笔记/`，但该 vault 实际只有 `工作笔记/`、`数据采集/`、`私密配置/`。
- 实际存在的 `数据采集/` 在地图里没有分类规则。

→ 新版技能首次运行即应触发 3.3 维护流程，向用户提出修正方案。

## 5. 设计要点与边界

- **地图是单一事实来源**：AI 不凭记忆或猜测决定分类，一切以地图为准。
- **写地图需授权**：创建和修改 `笔记地图.md` 都要用户确认；普通笔记的追加/新建不需要。
- **安全底线**：不读取/不写入私密配置；不在笔记正文记录密钥类信息。
- **不覆盖**：只追加或新建，永不覆盖已有笔记。
