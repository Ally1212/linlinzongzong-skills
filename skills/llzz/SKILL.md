# Llzz

## Goal

把用户给出的零散内容轻量整理后，写入本机 Obsidian vault 的 `林林总总` 目录。这个技能强调“随手记但可回看”：保留原意和现场感，只做必要结构化。

目标目录不写死，每次写入前先按“定位目标目录”流程自动搜寻本机 Obsidian vault。

## Locate target directory

写入前必须先定位“林林总总”目录，按以下顺序执行：

1. 运行技能自带脚本（推荐，stdout 即目标路径）：

   ```bash
   zsh scripts/find-vault.sh
   ```

   路径相对于本 SKILL.md 所在目录解析。若目标目录不存在需要创建，加 `--create`；怀疑路径变更，加 `--rescan`。

2. 脚本不可用时手动搜寻，优先级从高到低：

   - 解析 `~/Library/Application Support/obsidian/obsidian.json` 中注册的 vault 路径（按 `ts` 最近使用排序）。
   - 扫描 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/*`。
   - 扫描 `~/Documents`、`~/Obsidian`、`~/Notes` 等常见目录。
   - 以上目录中含 `.obsidian` 子目录的才是有效 vault。

3. 选择规则：

   - 第一个含有 `林林总总` 子目录的 vault 即为目标。
   - 所有 vault 都没有 `林林总总` 时，使用最近使用的 vault 下的 `林林总总`，首次写入时创建该目录。
   - 找到多个候选且无法判断时，列出候选让用户确认，不要静默选错 vault。

4. 定位结果缓存到 `~/.config/llzz/target-dir`；缓存失效时自动重新扫描。
5. 回复用户时说明最终写入的是哪个 vault 的哪个文件。

## Use when

- 用户说“林林总总”。
- 用户说 `llzz`。
- 用户说“记到林林总总”“整理到林林总总”“放到林林总总”。
- 用户提供截图、口述、杂乱文本、生活流水，并要求归档到“林林总总”。

Do not use when:

- 用户明确要求写入其他 Obsidian 目录或其他文件。
- 用户只是解释“林林总总”这个词，没有记录或归档意图。
- 用户要求严格专业分析，且没有要求归档。

## Workflow

1. 按“定位目标目录”流程确定本次写入的 `林林总总` 目录绝对路径。
2. 只基于当前用户提供的内容整理，不混入历史会话。
3. 如输入是图片，先转写可辨识文字；不确定文字标注“疑似”，不要编造。
4. 读取目标目录下现有 Markdown 文件列表，并尽量读取候选文件的标题、frontmatter、一级/二级标题和最近内容。
5. 根据“文件选择规则”决定追加旧文件或新建文件。
6. 使用 Obsidian Flavored Markdown 写入内容。
7. 写入后验证文件存在，并回复保存路径和 1-3 条整理摘要。

## File selection rules

AI 必须先判断主题相关性，再判断文件大小。

### Prefer appending to an existing file

当满足以下条件时，追加到已有文件：

- 当前内容和某个旧文件主题高度相关，例如同一健康问题、同一健身计划、同一装修事项、同一旅行、同一复盘主题。
- 旧文件标题、标签、摘要或最近内容能明显承接当前内容。
- 旧文件大小没有超过阈值。

推荐追加位置：

- 若旧文件存在同名或相近二级标题，追加到该标题下。
- 否则在文件末尾追加新的时间块。

### Create a new file

当满足任一条件时，新建文件：

- 没有明显相关旧文件。
- 内容是新的完整主题，例如一次新的旅行、一次新的复盘、一个新的健康/健身计划。
- 候选旧文件已经过大。
- 追加会让旧文件主题变杂，降低回看价值。

默认文件名：

```text
YYYY-MM-DD 简短主题.md
```

如果主题很碎、无法稳定命名：

```text
YYYY-MM-DD 林林总总.md
```

### File size threshold

- 默认把 `80 KB` 作为“文件过大”的硬阈值，超过则不要追加，新建文件。
- `60 KB` 以上作为软阈值：如果当前内容较长或主题可以独立成篇，优先新建。
- 文件大小可用 `wc -c` 或 `stat` 判断。

## Relevance scoring guidance

用简洁判断，不要写复杂分类器。

强相关信号：

- 同一实体：同一个人、地点、项目、医院、健身房、装修事项。
- 同一时间段：同一天或同一连续事件。
- 同一主题：健康饮食、腹胀打嗝、健身训练、装修、五一总结等。
- 用户明确说“补充到上次那个”“接着昨天的”。

弱相关信号：

- 只有同一个大类标签，例如都属于生活记录，但具体主题不同。
- 只是同一天，但内容没有承接关系。

决策原则：

- 强相关且未超大小阈值：追加。
- 弱相关：优先新建，除非用户明确希望放一起。
- 不确定：新建文件比污染旧主题更好。

## Note format

新建主题文件时使用：

```markdown
---
title: YYYY-MM-DD 简短主题
date: YYYY-MM-DD
tags:
  - 生活记录
---

# YYYY-MM-DD 简短主题

## 核心整理

- ...

## 待办

- [ ] ...

## 原始记录

> ...
```

追加到已有文件时使用：

```markdown
## HH:mm｜简短标题

### 简要整理

- ...

### 待办

- [ ] ...

### 原始记录

> ...
```

如果内容很短，可以只追加：

```markdown
## HH:mm｜随手记

- ...
```

## Cleanup rules

- 保留用户原意，不拔高、不扩写成报告。
- 轻量分点，合并明显重复表达。
- 自动提取待办：如“找时间”“要去”“记得”“下次”。
- 身体不适、重要风险、强时间敏感事项可以使用 Obsidian callout。
- 不要覆盖已有笔记；只能追加或新建。
- 不要把本技能说明写入笔记。

## Verification

写入后至少做一项验证：

- `test -f "<path>"`
- `wc -l "<path>"`
- `obsidian vault="<vault 名>" file path="林林总总/<file>.md"`

回复用户时说明：

- 最终定位到的 Obsidian vault 和目标目录。
- 写入了哪个文件。
- 是追加旧文件还是新建文件。
- 为什么这么判断，控制在一句话内。
