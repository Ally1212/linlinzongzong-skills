# Llzz

## Goal

以本机 Obsidian vault 根目录的 `笔记地图.md` 为「规则大脑」，完成笔记的写入、读取问答、地图初始化与维护。核心原则：**笔记地图是单一事实来源，每次读/写笔记前必读，严格按地图中的分类规则和用户偏好执行，不凭记忆或猜测决定分类。**

## Use when

- 用户说“林林总总”或 `llzz`。
- 用户说“记到林林总总”“整理到林林总总”“放到林林总总”。
- 用户提供截图、口述、杂乱文本，并要求归档到 Obsidian。
- 用户要求从 Obsidian 笔记中查找、读取、回答内容（如“查一下我笔记里关于 xxx 的记录”）。
- 用户要求初始化或整理笔记地图。

Do not use when:

- 用户明确要求写入其他软件或导出为其他格式。
- 用户只是解释“林林总总”这个词，没有记录或归档意图。

## Workflow 0: 定位 vault

每次执行前先定位 vault 根目录：

```bash
zsh scripts/find-vault.sh
```

路径相对于本 SKILL.md 所在目录解析；怀疑路径变更时加 `--rescan`。脚本优先选择含 `笔记地图.md` 的 vault；无法判断时列出候选让用户确认，不要静默选错 vault。

## Workflow 1: 笔记地图初始化（vault 无地图时）

1. 扫描 vault 全部目录与文件：只看目录结构、文件标题、frontmatter，不读私密内容正文。
2. 提出分类方案：分类数量与名称、每个分类的范围、现有文件的归属建议、命名规范。
3. **必须经用户同意后**，参照 `references/笔记地图模板.md` 创建 `笔记地图.md`；用户有异议则按反馈调整后再次确认。

## Workflow 2: 笔记地图维护（每次使用时顺带检查）

读取地图后对照实际目录结构检测漂移：

- 地图引用的目录是否还存在。
- 实际存在的目录是否都有对应分类规则。
- 规则是否过时。

处理权限：

- **小修正自动改**：修复失效链接、为已存在的目录补充缺失的规则、更新 `updated` 日期。改完在回复中一句话说明。
- **结构性变更需确认**：新增/删除/合并分类、修改写入偏好或安全规则，先提议，用户同意后再改。

## Workflow 3: 写入笔记

1. 定位 vault，读取 `笔记地图.md`，提取分类规则与写入偏好。
2. 只基于当前用户提供的内容整理，不混入历史会话；输入是图片时先转写，不确定的文字标注“疑似”。
3. 判断内容属于地图中的哪个分类。
4. 目标文件夹不存在 → 按地图规则自动创建。
5. 内容不命中任何现有分类：
   - 地图限制分类数量 → 归入最接近的分类或询问用户，**不擅自新增顶级分类**。
   - 无限制 → 可提议新分类，用户确认后才加入地图。
6. 在分类内决定追加旧文件还是新建文件（见“文件选择规则”）。
7. 使用 Obsidian Flavored Markdown 写入；只追加或新建，永不覆盖已有笔记。
8. 写入后验证文件存在，回复：vault 名、写入路径、追加/新建、判断理由（一句话）。

## Workflow 4: 读取 / 问答

1. 定位 vault，读取 `笔记地图.md`。
2. 推断用户问题最可能对应哪个分类文件夹，**优先在该文件夹内搜索**（文件名 → 标题 → 正文）。
3. 未找到 → 再全量搜索。
4. 私密配置目录默认不读，除非用户明确要求。

## File selection rules

先判断主题相关性，再判断文件大小。

### Prefer appending to an existing file

- 当前内容和某个旧文件主题高度相关：同一健康问题、同一健身计划、同一装修事项、同一旅行、同一复盘主题。
- 旧文件标题、标签或最近内容能明显承接当前内容。
- 旧文件大小没有超过阈值。

追加位置：旧文件有同名/相近二级标题则追加到该标题下，否则在文件末尾追加新的时间块。

### Create a new file

- 没有明显相关旧文件。
- 内容是新的完整主题。
- 候选旧文件已过大。
- 追加会让旧文件主题变杂。

默认文件名：`YYYY-MM-DD 简短主题.md`；内容很碎无法稳定命名时用 `YYYY-MM-DD 林林总总.md`。

### File size threshold

- `80 KB` 以上：硬阈值，必须新建。
- `60 KB` 以上：软阈值，内容较长或可独立成篇时优先新建。
- 用 `wc -c` 或 `stat` 判断。

### Relevance guidance

强相关：同一实体（人/地点/项目/医院/健身房）、同一连续事件、同一主题、用户明确说“接着上次的”。
弱相关：仅同一大类标签、仅同一天但无承接。
不确定时新建文件比污染旧主题更好。

## Note format

新建主题文件：

```markdown
---
title: YYYY-MM-DD 简短主题
date: YYYY-MM-DD
tags:
  - 生活记录
---

# YYYY-MM-DD 简短主题

## 核心整理

- ...

## 待办

- [ ] ...

## 原始记录

> ...
```

追加到已有文件：

```markdown
## HH:mm｜简短标题

### 简要整理

- ...

### 待办

- [ ] ...

### 原始记录

> ...
```

很短的随手记只追加：

```markdown
## HH:mm｜随手记

- ...
```

## Safety rules

- 不读取/不写入私密配置目录，除非用户明确要求。
- 笔记正文不记录 API key、token、密码、证书私钥；只写存放位置或 key 名。
- 永不覆盖已有笔记，只追加或新建。
- 创建和修改 `笔记地图.md` 的结构性变更必须经用户确认。

## Verification

写入后至少做一项验证：`test -f "<path>"` 或 `wc -l "<path>"`。

回复用户时说明：

- 最终定位到的 vault 和目标文件夹。
- 写入了哪个文件，追加还是新建，为什么（一句话）。
- 若顺带做了地图小修正，一句话说明改了什么。
